Monster Hunter Frontier Z on Linux

Mezeporta launcher, portable Wine prefix, and the Hunsterverse private server.

Tested on CachyOS (Arch) with KDE Plasma 6 on Wayland, NVIDIA RTX 3060 Ti, Mezeporta v1.5.4. Client patch by EclipseKnight, launcher by LilButter.

1. What you need

  • A Windows copy of the MHF-Z client, the folder named Monster Hunter Frontier Online (about 5.5 GB). It must contain dat/, mhf.exe, mhfo.dll, mhfo-hd.dll, mhl.dll and mhf.ini.
  • An Arch-based distribution (CachyOS, EndeavourOS, Manjaro, plain Arch).
  • About 12 GB of free disk: 5.5 GB client, 0.8 GB prefix, plus backups.
  • Your Hunsterverse account. You will type the username and password yourself; nobody needs to see them.

Check the source. The base client comes from the community, not from Hunsterverse. The server patch is the part Hunsterverse actually maintains, and it must be applied after the client, as in the patch step. If a link looks different from these, verify it before you run anything.
Keep your original client. Everything here works on a copy. The Windows folder is never modified, and the patch step backs up every file it replaces.

2. Packages and 32-bit support

MHF-Z is a 32-bit game, so Wine needs the multilib repository. Check it:

grep -q '^\[multilib\]' /etc/pacman.conf && echo "multilib enabled" || echo "multilib NOT enabled"

If it is not enabled, edit /etc/pacman.conf, uncomment both the [multilib] header and the Include = /etc/pacman.d/mirrorlist line under it, then refresh:

sudo pacman -Sy

Install the runtime dependencies:

sudo pacman -Syu --needed wine winetricks cabextract p7zip fuse2 \
  gstreamer gst-plugins-base gst-plugins-good gst-plugins-bad \
  gst-plugins-ugly gst-plugin-pipewire gst-libav \
  vulkan-tools mesa-utils gamemode

If everything is already installed, this is a no-op. You do not need a full system upgrade for this game.

3. Copy the game client

Put it in ~/Games/MHFZ. Replace the source path with wherever your copy lives, including a mounted Windows drive.

mkdir -p ~/Games/MHFZ
rsync -rlt --info=progress2 "/path/to/Monster Hunter Frontier Online/" ~/Games/MHFZ/

Verify the six required files exist:

cd ~/Games/MHFZ
ls mhf.exe mhfo.dll mhfo-hd.dll mhl.dll mhf.ini dat/mhfdat.bin

A clean client is about 5.2 GB and roughly 6,700 files.

4. Apply the client patch

Download the server's patch, back up the five files it replaces, then overlay it.

BASE="https://github.com/EclipseKnight/hvmhfz.eclipseforge.xyz/releases/download"
curl -L -o /tmp/Frontier_Patch.zip "$BASE/client_patch/Frontier_Patch.zip"

cd ~/Games/MHFZ
mkdir -p original-files/dat
cp -p mhf.exe mhfo.dll mhfo-hd.dll mhl.dll original-files/
cp -p dat/mhfdat.bin original-files/dat/

unzip -q /tmp/Frontier_Patch.zip -d /tmp/fp
rsync -rlt /tmp/fp/Frontier_Patch/ ~/Games/MHFZ/

The patch contains exactly five files: mhf.exe, mhfo.dll, mhfo-hd.dll, mhl.dll and dat/mhfdat.bin. The copies in original-files/ let you roll back at any time.

5. Install the Mezeporta launcher

Download the Linux build of the launcher and unpack it next to dat/, not inside it.

MURL="https://github.com/LilButter/Mezeporta/releases/download/v1.5.4"
curl -L -o /tmp/Mezeporta-Linux.zip "$MURL/Mezeporta-Linux.zip"

unzip -q /tmp/Mezeporta-Linux.zip -d ~/Games/MHFZ
chmod +x ~/Games/MHFZ/run-mezeporta.sh ~/Games/MHFZ/mezeporta-bin

Afterwards the folder looks like this: dat/, mhf.ini, mhfo.dll, mezeporta-bin, run-mezeporta.sh, Mezeporta/. Check newer releases before you start; anything v1.5.4 or newer works the same way.

6. Create the portable Wine prefix

The launcher expects its Wine prefix inside the game folder. The bundled script sets it up and installs DXVK, d3dcompiler_47 and the Visual C++ runtime into it:

cd ~/Games/MHFZ
bash SetupDeps/install-deps-arch.sh --portable-prefix "$HOME/Games/MHFZ"

This creates ~/Games/MHFZ/Mezeporta/WinePrefix (about 800 MB). Add --controller-fix if you use a gamepad:

bash SetupDeps/install-deps-arch.sh --portable-prefix "$HOME/Games/MHFZ" --controller-fix

Verify at the end:

bash SetupDeps/install-deps-arch.sh --verify

7. Launch wrapper (two Linux fixes)

On KDE Wayland with an NVIDIA card, the launcher window needs two environment variables. Create this small wrapper in the game folder:

cat > ~/Games/MHFZ/run-mezeporta-x11.sh <<'EOF'
#!/usr/bin/env sh
export GDK_BACKEND=x11
export WEBKIT_DMABUF_RENDERER_FORCE_SHM=1
exec "$(dirname "$0")/run-mezeporta.sh" "$@"
EOF
chmod +x ~/Games/MHFZ/run-mezeporta-x11.sh

Why each one:

VariableProblem it solves
GDK_BACKEND=x11Without it the launcher dies at startup with Gdk-Message: Error 71 (Protocol error) dispatching to Wayland display.
WEBKIT_DMABUF_RENDERER_FORCE_SHM=1Without it the window opens but stays blank, because WebKitGTK cannot allocate a GBM buffer on the NVIDIA driver (Failed to create GBM buffer ... Invalid argument).
Do not start the launcher from a systemd transient unit. The launcher exits once it hands off to the game, and the default KillMode=control-group then kills the game process with it. The game dies about 10 seconds after the launcher window closes. Start it from a terminal, a desktop shortcut, or with setsid nohup.

8. Set the launcher options

Run the wrapper and wait for the launcher window:

~/Games/MHFZ/run-mezeporta-x11.sh

On first run it shows the empty state:

Open Configure Settings, then the Advanced tab, and set Wine Prefix to Portable (Mezoperta). The prefix path should point at ~/Games/MHFZ/Mezeporta/WinePrefix, and the status line should say the prefix is ready.

The other tabs hold cosmetic options. Server Mode is not here: it is a property of each server and is chosen when you add or edit one.

9. Add the Hunsterverse server

Back on the main screen press ADD A SERVER and fill it in like this:

SignV1 matters. Hunsterverse uses a sign server. With the API mode selected the login fails or the game cannot reach the character server.

10. Log in and launch

Select Hunsterverse in the Server Selection dropdown, type your own account name and password, and press LOG IN. Pick a character, then launch.

The launcher window closes when the game starts. That is normal, as long as you did not start the launcher inside a systemd unit (see step 7). The game window is titled MONSTER HUNTER FRONTIER Z.

11. Troubleshooting

SymptomCause and fix
Launcher exits instantly with Gdk-Message: Error 71Native Wayland path. Start it through the wrapper with GDK_BACKEND=x11.
Launcher window is blank or blackWebKitGTK GBM failure on NVIDIA. Add WEBKIT_DMABUF_RENDERER_FORCE_SHM=1. WEBKIT_DISABLE_DMABUF_RENDERER and WEBKIT_DISABLE_COMPOSITING_MODE do not fix this one.
Launcher closes and nothing appears, every timeThe launcher is being run under systemd-run. Its unit is killed together with the game when the launcher exits. Start it directly, or with setsid nohup.
Game starts then quits after a few secondsCheck journalctl --user -u <unit> if you used a unit, otherwise run the launcher from a terminal and read the output. A DXVK or Wine error appears there.
Text in game is boxes or garbageInstall noto-fonts-cjk, enable ja_JP.UTF-8 in /etc/locale.gen, run sudo locale-gen, then start with LANG=ja_JP.UTF-8 ~/Games/MHFZ/run-mezeporta-x11.sh.
No soundInstall gst-plugin-pipewire and gst-plugins-good, then re-run the --verify step.
Wrong or broken prefixDelete ~/Games/MHFZ/Mezeporta/WinePrefix and re-run the --portable-prefix step. Your game files are untouched.
Want vanilla files backCopy everything from ~/Games/MHFZ/original-files/ back over the game folder.

13. Other distributions

The launcher and the game do not care which distribution you use, only that Wine, winetricks and GStreamer are present. On Debian or Ubuntu:

sudo dpkg --add-architecture i386
sudo apt update
sudo apt install wine wine32:i386 winetricks cabextract p7zip-full \
  gstreamer1.0-plugins-base gstreamer1.0-plugins-good \
  gstreamer1.0-plugins-bad gstreamer1.0-plugins-ugly \
  gstreamer1.0-pipewire vulkan-tools mesa-utils gamemode

Use scripts/linux/install-deps-ubuntu.sh from the launcher release for the prefix instead of the Arch script, and keep the same two environment variables in the wrapper.

Appendix: English text and language

MHF-Z is a Japanese game. The English translation is not a separate installer: it lives inside mhl.dll, the client's text layer, and that one file decides which language you see.

What the client patch already does. The Hunsterverse patch ships its own mhl.dll, so a normal install from the patch step is already translated. If your menus are English, you are done and should leave this file alone.

If your game is in Japanese. Your source client was untranslated, or something overwrote the patched DLL. Translation packs ship alternate builds of the same file. The pack this guide was written from contains two, mhfz_mhl.dll_custom and mhfz_mhl.dll_og. Swap the custom build in, keeping the server build safe:

cd ~/Games/MHFZ
cp -p mhl.dll mhl.dll.server         # keep the server patch build safe
cp -p "/path/to/client pack/mhfz_mhl.dll_custom/mhl.dll" mhl.dll
# launch and check the menus; still Japanese?
cp -p mhl.dll.server mhl.dll        # restore, then try the other variant

In that pack the _custom folder is the modified build to try first and _og is the untouched original. Folder names vary between packs, so use whichever pair came with yours.

If the game stops connecting after a swap, put mhl.dll.server back. The server patch build is what Hunsterverse expects, and a translation build from a different client version can be rejected.

Coverage is partial. Community translation updates do not translate everything. Item names, NPC dialogue and event text often stay Japanese even with the English DLL in place. That is the translation, not a broken install.

Fonts. If Japanese text shows as boxes, install noto-fonts-cjk and start the launcher with LANG=ja_JP.UTF-8 on Linux, or add the Japanese language pack on Windows (Settings, Time and language, Language and region, Add a language).

Two warnings from old client guides. Do not apply the hosts-file trick that circulates with the client pack: it points Capcom hostnames at 127.0.0.1, it is meant for self-hosted Erupe servers, and it will break name resolution for Hunsterverse. And Locale Emulator is only needed if the game refuses to start without a Japanese locale: Mezeporta launches the game itself, so try without it first.
