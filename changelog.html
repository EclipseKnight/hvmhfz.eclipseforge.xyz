Server changelog

Every update to Hunsterverse, newest first. A new entry is added each time an update goes live.

Last update listed: 29 October 2026. Page updated 29 October 2026. Found a problem that isn't listed? Report it.

Released updates are on the server, one dated entry per update. Coming next is finished and tested, but not on the server yet. It goes live at a future server restart.

Where a fix says "the game waited forever", the game was waiting for an answer the server never sent, or the server answered in a form the game couldn't read. You saw a stuck "communicating" screen, or a list full of junk.

Most fixes come from checking exactly what the game expects from the server, so we don't have to guess. Only fixes we are sure of go live.

Coming next (not live yet)

Finished and tested on our test setup, but not on the server yet. These move to Released updates when they go live.

Saving

  • A save the server can't load: the game no longer waits forever. It shows "Failed to transfer data from server. Please relog." instead.
  • Small save changes are no longer silently lost.
  • Plates: saving your plate data and plate box after clearing a plate no longer fails and leaves them out of date.
  • Older characters: Hunter Navi saves (about 4,800 characters have the older, smaller format) and plate saves that grow no longer fail.
  • A save the server fails to store: the game now keeps your change and tries again at the next autosave, instead of thinking it was saved. This covers your partner, Hunter Navi, Felynes, plates, house decoration sets and Hunting Road progress.
  • Hunter Navi: a failed read can no longer overwrite your Hunter Navi with a blank one.

Hunter Festival

  • Prize lists: never longer than the game can show, so the prize screens can't freeze, even if the trials and prizes are loaded twice again.
  • Trials: at most 255 are sent, all the game counts, so every trial you see earns souls.
  • Signing up: if a vice-leader signs the guild up before the leader, the whole guild no longer shows as guildless. Each guild has one registration.
  • Voting: after you vote, the vote row greys out as it should.
  • Delivering souls: when the server can't store your souls, the game keeps them for your next delivery. Before, the server could say they were stored when they weren't.
  • The final reward is given once per player.

Raviente (Great Slaying)

  • Player limits: the event's player limit now holds, so extra players can't squeeze in past it.
  • One player at a time on the phase vote and on the support menu, as the game expects.
  • Coming back after a reset: a player whose save still points at an old Raviente is no longer dropped into the running one. That split the room into two groups that didn't see each other's damage or support. The game now starts that player fresh.
  • Frozen event fixed: one server error could freeze damage and support for everyone on that channel until a restart.

Diva Defense

  • Event screens answer with empty lists and rankings instead of junk, or instead of waiting forever. This covers the bonus quests, the ranking rewards and the tactics log.
  • Spending Diva Defense shop coins no longer leaves the exchange screen stuck.
  • One step of the tactics screens no longer gets stuck.

Diva Defense itself isn't built on our server yet. These fixes stop the screens from getting stuck and filling with junk.

Sky Corridor (Tower)

  • Resetting your tower skills is now saved. Before, the reset was lost.
  • When the database fails, the game shows its failure message instead of pretending the change worked.

Rasta (lending your hunter to others)

  • Your Rasta ID: saving can no longer change or take over another player's Rasta ID.
  • Borrowing a Rasta: contracts stay as they are. Borrowing another Rasta no longer silently replaces someone's current contract.
  • The 3-borrower limit: a borrower who sends the same contract again no longer counts twice toward it.

Guilds and alliances

  • Server-side permission checks: guild, alliance, festival, gift and shop actions now check that you belong to that guild, hold the needed role, and can afford the action. Normal play is unchanged.
  • Removed from a guild, then acting in it: leaving, or changing the comment, motto, icon or "avoid leadership" setting, now shows the failure message instead of waiting forever. So do accepting, rejecting or kicking members.
  • Guild graduation (leaving a rookie or return guild that way) shows the failure message, because it isn't built on our server yet. Before, the game showed you out of the guild while the server kept you in.
  • Deleted alliances: an alliance whose main or sub guild was deleted no longer breaks guild screens.
  • Failures shown honestly: disbanding, resigning, applying, creating or disbanding alliances, guild adventures, mail, message board likes and guild points now show the game's failure message when the server couldn't do them. Before, they showed as done.
  • Guild adventures: they can only be collected after they return, and a failed list no longer lets a guild start a second adventure.

Gifts, gacha, shops and the cafe

  • Gifts (distributions): each one can only be claimed as many times as it allows, and only by players who qualify. Gift RP is added together with the claim.
  • Gacha without prizes: a gacha whose prizes couldn't be read, or that has none, no longer takes your coins or Frontier Points. The screen closes and the game gives the cost back.
  • Stored gacha prizes: a server error while you collect them no longer deletes them.
  • Cafe items that cost more than your cafe points no longer leave your points negative.
  • Daily cafe bonus:
    • The game's check no longer uses up the day's bonus before you claim it, so the claim now gives you the bonus.
    • It can't be given twice because of a server error.
    • It isn't marked as taken when the points weren't added.
  • Equipment appearances you unlock are no longer lost when the server can't read your list first.

Signing in, the world list and lobbies

  • 255 friends or guildmates: signing in with exactly 255 (over all your characters) no longer garbles the rest of the sign-in data.
  • The world list is no longer dropped by the game for some numbers of worlds and channels.
  • Friends who disconnected: a friend or guildmate left with an old sign-in session no longer shows as on no server.
  • Errors while entering a world no longer leave you on the loading screen forever.
  • Player search: joining a player you found now takes you to the land they're in.
  • Lobby search shows only the lobby you asked for, and no longer crashes on some lands.

Quests and parties

  • Caravan scores: your caravan score now posts at the end of a quest. Before, it always failed and added 0.
  • Seibattle score lists show clean names, with no junk at the end.
  • Party counts: guests in a quest party get the same party counts as the host. Before, guests always got the default, so a quest value split by party size could differ from the host's.
  • Tournament quests no longer get stuck when you enter one.
  • Reward songs:
    • Using one no longer gets stuck. It has no effect yet.
    • The end of a quest no longer gets stuck at the step that counts them.

Houses

  • Bookshelf: visitors to your house now see your bookshelf as you do, instead of entries made up from other parts of your save. Display only; your save was never affected.

Server stability

  • A rare crash that could disconnect everyone at once is fixed.
  • Errors without crashes: dozens of server errors now get a clean failure message, or an empty list, instead of a crash or a screen that waits forever.
  • Hunting Road: Road data that failed to load can no longer be saved over your real progress.

Released updates

29 Oct 2026: Quest catalog and English quest text

  • Quest catalog: every quest on the server, searchable by name, monster, area, rank and type, with monster icons and 40 per page (/quests.html).
  • English quest titles: all 9,157 quest names are translated and written into the game's own quest files, so the quest counter and the site agree. Files were patched in place at the same size, with a full backup taken first.
  • Quest pages: each quest has its own page with category, area, objective, time limit, reward money, client and the monsters it names, each linked to its monster page.
  • Monster names checked against the wiki: 蛮竜 is Gurenzeburu and Zamuza is Taikun Zamuza; titles that used the wrong name and the game's own "Emporer" spelling are corrected in place.

29 Oct 2026: Quest logs for every hunter

  • Hunter profile: a quest log under the Profile tab, newest first, 20 per page, with the result, time in the quest and clear time.
  • Account Hunts tab: the same log for whichever character you pick.
  • Party: each logged quest names the other hunters who were in it at the same time. Quest and hunter names link to their pages.

29 Oct 2026: Worlds page and quest outcomes

  • Who's online now sits above the player count graph, and each hunter on a quest shows how long they have been in it.
  • Quest log panel: clears, fails, average time in quest and average clear time for the last 24 hours, plus the latest quests and the most run.
  • Outcomes recorded: the game server now stores whether a quest was cleared or failed and its clear time; older stays stay blank because the server never saw their end.

29 Oct 2026: Admin and security

  • Audit log in the database: one collapsible block per server run, with its date and time and only the actions from that run; the file stays as a fallback.
  • Sign-in limit: 20 attempts per address every 10 minutes on top of Turnstile.
  • CORS narrowed on signed-in endpoints to the site origin, and a Discord secret that was being printed to the service log was removed. The bot also no longer lets a player name ping @everyone.

29 Oct 2026: New launcher button and dialog art

  • Launcher: the buttons are now a leather band and the popup dialogs a torn parchment with a speech bubble for the message, in both the classic and PS4 styles. The labels and buttons still draw on top, so the "Sign in", "Start game" and dialog buttons read exactly as before.
  • Classic style: each button has a slightly darker hover state, so a click reads clearly.
  • Updating screen: the parchment is also the background while the launcher updates the game.
  • No download: the launcher fetches these images from the game server each time it starts.

29 Oct 2026: Hunting Road leaderboard

  • Game server: each floor you clear on the Hunting Road is now recorded. Leaderboards ranks every rotation: the highest floor reached in one run wins, and whoever got there first wins a tie. The open Road and the Solo Road have their own boards. When a rotation ends you can still open its board.
  • Before this update: floors reached earlier still show on your in-game record page, but they do not count on a rotation's board.

28 Oct 2026: Hunter profiles from the Worlds board

  • Click a name: on the live board on the Worlds page, each hunter's name, in the list and in the parties, now opens that hunter's profile directly.
  • Same name in a party: if two hunters on the same world share a name, that name opens a Hunters search for it instead.

28 Oct 2026: Quest parties on the Worlds board

  • Who's questing together: the live board on the Worlds page now lists the parties on each world: which quest, and which hunters are in it. Hunters in a party get an "In party" tag in the list.
  • Quests are listed by their number, as the server sees them. "Quest loading…" means the party has just left and the quest is still loading.

28 Oct 2026: New launcher banners and background

  • Four new banners rotate at the top right of the Mezeporta launcher, in place of the placeholders. Click one to open its page: Feeling Lucky? (the home page), Weekly Leaderboards (Leaderboards), Custom Road Challenge (Road builder) and Set Builder (Set Builder).
  • A new background: the classic launcher now shows the Hunsterverse background picture behind the login box, in place of the placeholder.
  • Nothing to install: the launcher loads them from the server the next time you open it. There was no server restart.

28 Oct 2026: Who's online, live on the website

  • Live board: the Worlds page now shows who is online right now: how many hunters are online, in town and on a quest, and a list of each character, their world, whether they are in town or on a quest, and which quest. It refreshes every 30 seconds.
  • The Worlds board shows each hunter's Discord display name when their account is linked.
  • Quests are listed by their number, as the server sees them: quest names live in the game client. "Departing" means the hunter has just left for a quest that is still loading.
  • The game server restarted once for this, at 05:47 UTC, while nobody was online.

28 Oct 2026: A new launcher header

  • The Mezeporta launcher's ZZ header is now the animated Hunsterverse logo, in place of the placeholder. It shows in both the classic and the PS4 style.
  • Nothing to install: the launcher loads it from the server the next time you open it. There was no server restart.

28 Oct 2026: Hunting Road, ready for more monsters

  • Behind the scenes: the server tool that puts the winning Road in the game now accepts any of the game's 176 monsters, not only the ones the Road already uses. A monster new to a table gets its level and settings from that table's other monsters.
  • Nothing changes in the builder yet: the Road builder still offers the Road's current monsters. More monsters come to the builder in a later update.
  • The current Road and the vote dates are unchanged, and there was no server restart.

27 Oct 2026: A new Hunting Road

The winning Road design is now the group Hunting Road for the current rotation. It stays until the first Road voted on this site replaces it, after voting closes on 17 Nov 2026 (Hunting Road). The solo Road is unchanged.

  • New monsters on every floor: every floor now draws from the same 20 Zenith monsters: Rathalos, Khezu, Daimyo Hermitaur, Blangonga, Hypnocatrice, Tigrex, Espinas, Aqra Vashimu, Hyujikiki, Giaorugu, Midogaron, Rukodiora, Plesioth, Toridcless, Bogabadorumu, Doragyurosu, Gasurabazura, Gravios, Baruragaru and Harudomerugu (floor 56 offers 11 of them). Doragyurosu, Gasurabazura, Gravios, Baruragaru and Harudomerugu no longer have to be unlocked first. White Fatalis no longer appears on every 10th floor.
  • Floor 60 fixed: in the design as sent, floor 60's Blangonga was set to the wrong form. We fixed it before release: it's the Zenith Blangonga, like every other monster on that floor.
  • More Road points: the points multiplier is now x2 on floors 1-9, x3 on 11-19, x4 on 21-29, x5 on 31-39 and x6 from floor 41 (it was x1 to x4). Every 10th floor is a bonus floor: x10 on floor 10, x15 on 20, x20 on 30 and x25 on 40, 50 and 60.
  • Still 60 floors: after floor 60 you go back to floor 41, as before.

27 Oct 2026: Hunting Road, built by players

  • Build your own Hunting Road on the website (Road builder, signed in). For each table, pick which monsters it offers, how often, and which one is always offered. Then pick which table each floor uses. The builder checks your Road as you edit, so a Road that would break the game can't be sent.
  • Every two weeks there's a new Road. You get two weeks to send your Road and one week to vote (Hunting Road). Then the winner becomes the open Hunting Road for everyone, with no server restart. The first round is open now: send your Road until 10 Nov 2026, 18:00 UTC, vote until 17 Nov 2026, 18:00 UTC.
  • Past winners are listed with their creator's character (Road history).
  • The winner gets a reward to claim on the account page, for the character of their choice.
  • Also fixed: searching hunters, guilds and the item catalog on the website works again. Before, typing did nothing.

27 Oct 2026: Hunsterverse launcher (API mode)

  • The Mezeporta launcher's API mode works on Hunsterverse. Set the server's Launcher Port to 8080 and leave Mode on API (see the Windows or Linux guide).
  • The launcher now shows Hunsterverse news, banners and links, and your mail and unclaimed gifts. The artwork is a placeholder for now.
  • SignV1 mode (Launcher Port 53312) still works as before.
  • Linux players: keep the Wine prefix outside the game folder. A prefix in Mezeporta/WinePrefix makes the launcher's update step fail ("Patcher failed to manage files in game folder"). The Linux guide, step 6 shows how to move it.

26 Oct 2026: Hunter Festival data cleaned up

The Hunter Festival (Hunter Festa) is the event where guilds are split into two teams (blue and red) and earn souls from festival trials. The winning team gets the prize screens and winner quests.

  • The problem: the server's festival trials and prizes had been loaded three times over. The prize lists became too long for the game, so every prize screen at the festival counter would have frozen. The game also only counts up to 255 trials, so most of the 369 trials earned no souls.
  • The fix: we removed the exact duplicates before the prize phase opened. 123 trials and 120 prizes remain, all unique. Votes already cast still count.

25 Oct 2026: Discord bot back online

The FrontierBot was offline: Discord changed its rules for large servers. It's back and now uses slash commands (type / in Discord):

Also fixed:

  • /resetpassword with a password the account site doesn't accept no longer gets stuck retrying.
  • /link with a wrong code now says it failed. Before, it said it had worked.

23 Oct 2026: Game server upgrade

The server software (Erupe, the open-source MHF server) moved to a newer version from August 2025, with our own fixes on top.

From the newer Erupe:

  • Weekly login stamps work again. The stamp card had failed at every check since about 11 October (around 3,300 database errors). There have been none since the upgrade.
  • Guild Poogie outfits: unlocking an outfit for your guild's Poogie now saves correctly. Before, the outfit could unlock wrongly or not at all.
  • Joining a party's quest: if the host's data never arrives, the game no longer waits forever. The server now gives up after about 10 seconds.
  • Stability:
    • Fixed a crash when many players loaded quests at the same time.
    • Fixed problems in how the server sends data.
    • Fixed problems in how it cleans up old logins.

Our own fixes:

  • Guild missions: setting, cancelling and counting a guild mission target. The game used to read leftover memory instead of the server's answer.
  • Guild applications: the game now gets the answer it expects when you apply to a guild.
  • Guild actions the server doesn't know no longer leave the game waiting with no answer.
  • Guild scouting: the "refuse scouts" setting and an empty scout list now load properly.
  • Diva Defense: prayer gems, collecting items and adding Diva points now get answers the game can read.
  • Big guilds: the guild hunt list holds up to 127 entries, all the game can show. With 128 or more it failed to load at all.
  • Order rankings and the daily cafe-point check now answer in the form the game reads.
  • Hidden packet mix-ups (four): prayer gems, Diva Defense items, removing a message board post, and the guild's Sky Corridor (Tower) requests each sent more data than the server read. The leftover bytes scrambled whatever the game sent next. Now all of it is read.

23 Oct 2026: Poogie Dressup! gift fixed

The "Poogie Dressup!" gift in the gift list should give Poogie outfits 1-30, but it had been gifting one empty outfit. Up to about 2,500 characters claimed it and got nothing.

  • It now gives all 30 outfits. We tested it: the outfits arrive and can be equipped.
  • It can be claimed twice, so anyone who already got the empty gift can claim it again.

Known issues

  • The launcher in our client patch is broken. Use the Mezeporta launcher: see the Windows guide or the Linux guide.
  • Usernames are case-sensitive. Logging in as eclipse instead of Eclipse creates a new, empty account. Your real save isn't lost: log in again with the exact capitals.
  • Raviente rewards: if you leave before the phase vote and the event resets, you can come back to "the event is over" with no reward. A fix is planned.
  • Not built on our server yet: Diva Defense, reward song effects, tournaments and guild graduation. The fixes above stop them from getting stuck, but they don't work yet.

Changing a room's Road now moves everyone onto it

29 Oct 2026
  • The server records which Road each client was served. When the room's Road changes, anyone still holding a different one is returned to town automatically, because the client only reads the Road file on town entry.
  • No more telling the party to step back and hoping: the reload is guaranteed before the next quest.

Quest text in English, and a drafts workspace for Roads

29 Oct 2026
  • Quest objectives, client names and descriptions are translated throughout: 5,461 objectives, 7,164 descriptions and 1,819 clients now read in English on the catalog and quest pages.
  • The Road builder keeps drafts on your account, so a half-finished Road survives a closed browser and can be picked up from another machine.

Saved Road preference and a drafts-friendly Road page

29 Oct 2026
  • The Account page can save the Road you play. Erupe pins it when you open a quest room, and a room can still override it with !road for that session.
  • Road history keeps every version with its dates and hash, so old Roads stay playable and their records stay readable.

Roads you can choose, and a board that survives a rotation

29 Oct 2026
  • Every Road the server has run is listed on the Road history page with its dates, status and hash.
  • When a Road retires its board is frozen as the original board; anything climbed afterwards goes to a separate revisit board, so going back never overwrites a record.
  • In game, a quest room can pick its Road: type !road to list what is installed, !road 2 to choose, !road clear to return to the live Road. Everyone steps back to town once so the client reloads it.
  • A scheduled job freezes the board the moment a rotation is replaced, so nothing depends on remembering to do it by hand.
