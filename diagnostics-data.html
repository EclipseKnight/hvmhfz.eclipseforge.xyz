    What the game's live diagnostics sends

    Everything the game's crash and usage reporting does, in plain words: when it sends, every field, what is never sent, who can see it, how long it is kept, and how to turn it off.

    In short

    With the new client patch (hvmods.dll 24 or later), the game sends two kinds of report to Hunsterverse: a small health report every few minutes (frame rate, where you are, errors the game noticed) and, after a crash, a crash report. We use them to find and fix bugs in the patch, the mods and the server.

    It is on by default, and you can turn it off at any time (see How to turn it off). Every line a report can hold is listed in Every field. A test on our side fails when the game sends a line this page does not list.

    In the owner's words: "We aren't stealing your data, we just need to know what your client is doing in order to identify issues."

    When it sends

    • Health report: the first one a minute after you log in (5 minutes after the game starts if you never log in), then every 5 minutes. A new error sends one sooner, but at most once a minute. A health report is about 1 KB.
    • Crash report: when the game crashes, it writes the crash file hvsend-crash.txt on your PC. It is sent at the next start of the game, because a game that is crashing cannot be trusted to send. The file is emptied once the server has taken it. A crash report is up to 64 KB.
    • Offline: up to 4 health reports and the waiting crash report are kept. When that queue is full, the newest report is dropped, and the next report says how many were dropped (the dropped: line).
    • No answer, or the server is busy: the report is tried again after 1 minute, then after twice as long each time, up to 15 minutes.
    • Refused: a report the server refuses is dropped, not tried again.
    • Switched off by the server: the server can answer 410, which switches sending off until you start the game again.
    • Does it slow the game? No. It sends on a background thread of its own, at low priority.

    Every field

    A health report holds the lines in the first two tables. A crash report holds the first table and then the crash file the game wrote on your PC, which holds the lines in the third table. The server also keeps the time it received the report.

    Both reports start with

    LineWhat it is
    HVTELEM 1The first line, "HVTELEM 1": the report format and its version.
    kind:"health" (the regular report) or "crash".
    session:A random number made new at every game start (from the clock and a tick count). It is not tied to your PC and changes every time.
    seq:The report's number in this game session: 0, 1, 2 ...
    time:Your PC's clock (UTC) when the report was made; for a crash, when the crash happened.
    edition:HD or SD: which game client you run.
    patch:The Hunsterverse client patch version (v1.24 = 124, v1.24-pre3 = 12403, 0 = an old patch without a version).
    hvmods:The version of hvmods.dll (our mods and diagnostics).
    character:The id number of the character you logged in with (0 before you log in). Never the name.
    running:Seconds since the game started (since hvmods.dll loaded).

    Health report

    LineWhat it is
    fps:Game steps per second over the last 5 seconds (the game's logic runs at about 30).
    drawn:Pictures drawn per second over the last 5 seconds (lower than fps when the PC cannot keep up).
    frames:Game steps since the game started.
    flags:The mod switches the server sent (a number).
    mods:The same switches as names (for example "damage numbers, damage meter").
    scene:none, town or quest.
    stage:The id number of the area you are in (0 when none).
    quest:The id number of the quest you are on (0 when none).
    connection:"open", or "closed" and the code the game gave when the connection to the server closed.
    requests:Since the last report: how many requests the game sent to the game server, how many failed and how many got no answer in 30 seconds. Counts only, never their contents.
    dropped:Reports thrown away while your PC was offline (the queue was full).
    [problems] linesKnown problems seen this session, one per line, for example a map file the game refused (with the file's name inside the game folder, never a full path).
    [errors] linesErrors since the last report (at most 16), one per line: the time, stage, quest and what failed: a game file refused, a map that fell back to Mezeporta, a server request that failed or got no answer, a disconnect.

    Crash report

    LineWhat it is
    HVCRASH 1The crash file's first line, "HVCRASH 1": its format and version.
    time:When the crash happened (your PC's clock, UTC).
    exception:The Windows error code and its name (for example "0xc0000005 access violation (read of 0x00000010)").
    at:Where in the game's code it crashed: the module's file name and an offset (for example "mhfo-hd.dll+0x0089f165").
    hvmods running:Which of our mods was running at that moment, if any.
    registers:The processor's registers at the crash (ten numbers, needed to read the crash).
    frames:Up to 16 code addresses of the calls that led to the crash (module file name + offset).
    stack:Up to 24 code addresses found on the game's stack (module file name + offset).
    client sections:The game DLL's section names, addresses and sizes (to see whether it is our patched DLL).
    [client] edition:HD (mhfo-hd.dll) or SD (mhfo.dll).
    [client] patch:The client patch version, as text and as a number.
    [client] hvmods:The version of hvmods.dll.
    [client] client base:The address the game DLL was loaded at.
    [environment] game exe:The game program's file name (for example mhf.exe).
    [environment] launcher:The file name of the program that started the game (for example Mezeporta.exe), or that it has ended.
    [environment] game folder modules:The file names of the DLLs loaded from the game folder (for example mhf.exe, mhfo-hd.dll, hvmods.dll, d3d9.dll). File names only, never the folder.
    [files] linesThe game's own files (mhfo-hd.dll, mhfo.dll, dat/mhfdat.bin, dat/mhfpac.bin, dat/mhfinf.bin, hvmods.dll and the game program): size and SHA-256 checksum, to see whether the patch installed fully. Never their contents.
    [server] flags:The mod switches the server sent, their names, and when they arrived.
    [server] keys:The key-binding settings the server sent for our mods (numbers).
    [server] last login:When you last logged in this session.
    [mods] started:Which of our mods started.
    [mods] refused:Which of our mods refused to start.
    [mods] meter:The damage meter's state (in a quest or not, how many monsters and hits, where it was drawn on screen), when the meter is on.
    [mods] move hits:How many hits had their move recorded, only when you switched on "Show move id" for damage numbers.
    [state] scene:Title screen, town or quest (with the game's state number), whether a menu was open, and whether you were disconnected.
    [state] stage:The area and map number you were in.
    [state] weapon:The weapon type you had (for example long sword).
    [state] quest:The quest's id, its file, class, the time left and carts left, and how long ago it started.
    [state] character:Your character's id, HR and GR points. The name is removed before sending.
    [state] connection:Which of the game's server connections was in use and whether it was open or closed (with the code).
    [problems] linesKnown problems seen this session (as in the health report).
    [events] linesThe last 50 things that happened, each with a time: logging in, area and quest changes, a menu opening, the connection closing, the mod switches arriving, server requests that failed or got no answer, game files refused, what our mods did. Messages from the server's own "Erupe" account read "server: (not sent)". Chat is never recorded.
    [requests] linesThe last 30 requests the game sent to the game server: the time, the request type number, an internal handle number, and whether it was answered, failed (error code) or was still waiting. Never their contents.
    [moves] linesThe last 200 moves you hit with (weapon, move id, damage), only when you switched on "Show move id" for damage numbers.
    [system] windows:The Windows version number (and the Wine version on Linux or Mac).
    [system] locale:Your Windows language setting and code page as numbers (for example 0x00000409, code page 1252), to explain text shown wrong.
    [system] memory:Total and free memory on the PC and how much the game used.
    [system] game running:How long the game had been running.
    [system] hvmods running:How long hvmods.dll had been running and since when.
    [system] fps:Game steps and pictures drawn per second in the last 5 seconds, and steps since the start.

    The crash part is the crash file the game wrote on your PC (hvcrash-<time>.txt) with two changes: the character line has no name, and messages from the server's own "Erupe" account read server: (not sent).

    What is never sent

    • Chat. Players' chat and the Discord relay's chat are never even recorded by the game. The server's own "Erupe" lines are replaced by server: (not sent).
    • Passwords.
    • Your character name. It is removed from the crash report's character line. Only the character's id number is sent.
    • Your Windows user name, and any folder path. Only file names are sent. As a second safety net, the server also replaces anything that looks like C:\Users\<name> with <user folder> before it stores the report.
    • Other players' data.
    • The contents of requests or files. Only counts, types, sizes and checksums are sent.
    • hvmods.log, screenshots and keystrokes.
    • Your IP address is not stored with the report. Our web server sees it while it receives the report, like any website, and does not keep it with the report.

    Where it goes

    Only to our own API, https://api.hvmhfz.eclipseforge.xyz/api/public/telemetry, over HTTPS (encrypted). There is no third party, and no advertising or analytics service. No sign-in is sent with it: on our side, the character id in the report links it to your account.

    Who can see it

    Hunsterverse staff with the Diagnostics permission: admins, moderators and helpers (helpers have Diagnostics by default; an admin can change staff permissions). And you, for your own characters, on the Account page (see below). It is never shown publicly.

    How long it is kept

    30 days, then it is deleted automatically (a daily job). You can delete your own reports earlier on the Account page.

    What we use it for

    • Find crashes, and which patch they come from.
    • Spot broken installs (the file checksums show a patch that did not install fully).
    • Map files that fail to load.
    • Server requests that fail or get no answer, and disconnects.
    • Frame rate per patch.

    Then we fix the patch, the mods and the server. We do not use it for bans, advertising or selling anything, and it is never shared outside staff.

    Files on your PC

    The game always writes these files, whatever the setting. They never leave your PC unless you upload them yourself. They are in the game folder (the folder with mhf.exe).

    FileWhat it is
    hvdiag.txtThe game's own report. Rewritten while the game runs: at the start, a few seconds after something worth knowing, every minute when anything changed, and at exit. It has your character name.
    hvmods.logWhat the mods did.
    hvcrash-YYYYMMDD-HHMMSS.txtOne per crash. The time in the name is UTC.
    hvsend-crash.txtA crash waiting to be sent. Empty when there is none.
    hvmods-telemetry.datYour choice: on or off.

    You can upload these files yourself on the Account page (Diagnostics) to get a plain answer about what went wrong.

    How to turn it off

    • The first time you are in town with the patch, the game shows a one-time notice, "Crash and usage data", with two buttons: OK and Turn off. Esc counts as OK.
    • At any time in the game: Ctrl+F10, Game options, the tab Data, "Send crash and usage data": On or Off.

    When it is off, sending stops at once, anything waiting is dropped before the next send, and a crash waiting to be sent is deleted. Nothing is built while it is off. The local files above are still written.

    Your choice is kept on your PC, in hvmods-telemetry.dat, so the notice shows only once. Deleting that file brings the notice back.

    Turning it off does not delete what was already sent. Delete that on the Account page.

    See and delete your own reports

    Sign in, open the Account page, "Live reports from your game". It lists every report of your characters and shows the full text of each one exactly as we stored it. The button "Delete my reports" deletes them all.
