API

Everything the site and the Discord bot show comes from one JSON service. Sign in with a game account to read your own data; admin accounts get the server tools and the audit log.

Base URL https://api.hvmhfz.eclipseforge.xyz · health at /actuator/health · times are UTC

Signing in

Two routes return the same signed token (valid 7 days). The token identifies the account; no endpoint takes an account id from the caller, so one token cannot read another account's data.

From a program

curl -s https://api.hvmhfz.eclipseforge.xyz/api/auth/signin \
  -H 'Content-Type: application/json' \
  -d '{"username":"YourGameName","password":"your-password","token":""}'
{"accessToken":"eyJhbGciOiJIUzI1NiJ9...","id":12345,"roles":["ROLE_USER"],"tokenType":"Bearer"}

Then send it on every account request:

curl -s https://api.hvmhfz.eclipseforge.xyz/api/account \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiJ9..."

From the site (Cloudflare Turnstile)

POST /api/auth/signinweb takes the same body plus the Turnstile answer in token. The site's form does this for you. Registration and password reset use POST /api/auth/signup and PUT /api/auth/passwordreset.

The token is a JWT: sub (account name), roles, exp, signed by the server. Editing the payload breaks the signature, so roles cannot be faked. The server checks the role on every request.

The Road board ranks the highest floor reached in one run during that rotation, then who reached it first. Entries carry the floor, when it was reached, how many floors were recorded in the rotation and the Road point balance at that floor. Rotations carry sha: the sha256 of the Road data file, the map's permanent id.

Your account

Send Authorization: Bearer <token>. The server reads the account from the token.

No raw save blobs are returned; the server decodes them. Asking for somebody else's character returns 404, not their data.

Admin endpoints and the audit log

Admin accounts (ROLE_ADMIN), some also open to moderators. The server checks the role on every call; the site only hides the buttons.

Server tools

  • GET /api/admin/ops/services state of the game server, the API and the bot, restart counts, players.
  • GET /api/admin/ops/services/{service}/logs?lines=200&errors=false recent log lines with secrets and player IPs masked.
  • POST /api/admin/ops/services/{service}/restart restarts the API or bot at once. For erupe it schedules the warned restart: 10 minutes of Discord and in-game messages, the bot status counts down, then the swap and restart. The call answers restart=scheduled immediately. One restart per service every two minutes.
  • GET /api/admin/ops/audit?max=500 newest-first audit entries: at, account, action, target, result.

Every admin action is written to the audit log: restarts, role changes, chat flags, gifts, Hunting Road cycles and entries, session cleanups. The admin page shows the same data under Audit with search, action and account filters, column sorting and CSV export.

Users, roles and gifts

  • GET /api/admin/users?q=&page=0&size=25 paged accounts with roles, characters, last login and flags.
  • POST /api/admin/users/{id}/flags body {"op":true,"timer":false}.
  • GET /api/admin/roles, POST /api/admin/roles body {"username":"Name","role":"ROLE_MODERATOR","grant":true}.
  • GET /api/dist/all, POST /api/dist/createDist gift lists.

Hunting Road

GET/POST /api/admin/road/cycles, PUT /api/admin/road/cycles/{id}, then close, approve, winner; entry actions hide, unhide, disqualify with {"reason":"..."}; POST /api/admin/road/pause with {"paused":true}. The player-facing routes live under /api/road and need an account token.

/api/road/deploy/next and /api/road/deploy/{cycleId}/result are for the game host's deploy timer and use the X-Road-Deploy-Token header, not an account token.

Errors, limits and caching

Errors are {"message":"..."}. Common codes: 400 bad input, 401 missing or expired token, 403 wrong role or not your character, 404 unknown id, 409 conflict, 429 rate limit, 502 an upstream tool failed.

Public responses are cached 30 seconds. Sign-in and the public endpoints are rate limited per client: back off on 429 instead of retrying in a loop.

Worked examples

Shell: token and gifts

TOKEN=$(curl -s https://api.hvmhfz.eclipseforge.xyz/api/auth/signin \
  -H 'Content-Type: application/json' \
  -d '{"username":"YourGameName","password":"your-password","token":""}' | jq -r .accessToken)

curl -s https://api.hvmhfz.eclipseforge.xyz/api/account/distributions \
  -H "Authorization: Bearer $TOKEN"

JavaScript: the weekly hunter board

const res = await fetch("https://api.hvmhfz.eclipseforge.xyz/api/public/leaderboards/hunts?period=week&board=hunters");
const board = await res.json();

Python: the Road board

import requests
board = requests.get("https://api.hvmhfz.eclipseforge.xyz/api/public/road/leaderboard",
                     params={"rotation": "current", "mode": "open"}).json()
for entry in board["entries"]:
    print(entry["rank"], entry["name"], entry["floor"], entry.get("points"))
